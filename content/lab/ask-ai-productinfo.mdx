## A missing heading path was the biggest bug, and no test saw it

Embedding only each chunk's text silently dropped the page title. The word
"install" appeared in 4 of 42 chunks by text alone, and in 28 of 42 once the
heading path was included. Adding the path took retrieval of the installation
guide from 1/10 to 9/10, and an early evaluation set from 19/23 to 23/23.
**The fix was not a better model; it was context the embeddings never saw.**

## Two mechanisms for a one-parameter problem

Three facts kept getting missed. I built two mechanisms for what looked like a
missing-information problem, and together they fixed only one of the three.
Widening the retrieval window from 10 to 50, as a diagnosis, showed the missing
facts sitting just past the old cut-off. **The bottleneck was retrieval depth,
a single parameter nobody had questioned before I built more machinery on top
of it.** The check that exposed it costs cents, and it should have come first.

## The PDF was not unparseable, it was corrupted

An exported PDF arrived with zero extractable characters. My first diagnosis,
a parsing-library failure, was wrong: 62% of the file was Unicode replacement
characters, the result of a lossy conversion in transport. **The bytes were
destroyed, not misread.** That moved ingestion directly from the source API
from a "maybe later" idea to the primary path.

## A harness that goes down as well as up

Gut feel would have called every change an improvement. A 21-case harness,
graded by a separate judge model, did not: a cheaper generation model dropped it
to 95.2%, and a change to the prompt brought it back. **A history that is not
monotonic is the sign the harness measures something real.**
